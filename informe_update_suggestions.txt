     **1.1 Resumen**
     El proyecto KineViz aborda la necesidad de optimizar el procesamiento y análisis de datos biomecánicos en la investigación kinesiológica. KineViz ofrece una herramienta de escritorio automatizada para la gestión integral de estudios, permitiendo la definición flexible de Variables Independientes (VIs) y sus sub-valores asociados, incluyendo la gestión de alias para mejorar la interpretabilidad. La plataforma integra datos cinemáticos, cinéticos y electromiográficos, realizando una detección automática de tipo de dato. KineViz facilita tanto análisis estadísticos discretos (generación de tablas resumen, pruebas t, ANOVA, etc., con visualizaciones como boxplots y swarmplots) como análisis continuos de series temporales mediante Mapeo Estadístico Paramétrico (SPM). El sistema está diseñado para optimizar la interpretación de la información, reducir significativamente los tiempos de procesamiento, y agilizar el flujo de trabajo de análisis, proporcionando a los profesionales e investigadores acceso a información crucial de manera eficiente. Adicionalmente, KineViz incluye funcionalidades robustas de copias de seguridad, restauración y una opción para deshacer eliminaciones recientes, asegurando la integridad y disponibilidad de los datos.

     **Palabras clave:** kinesiología, biomecánica, análisis de datos, software, Variables Independientes, SPM, automatización, visualización de datos, copias de seguridad.

     **1.2 Abstract**
     The KineViz project addresses the need to optimize biomechanical data processing and analysis in kinesiology research. KineViz offers an automated desktop tool for comprehensive study management, enabling flexible definition of Independent Variables (IVs) and their associated sub-values, including alias management for enhanced interpretability. The platform integrates kinematic, kinetic, and electromyographic data, performing automatic data type detection. KineViz facilitates both discrete statistical analyses (summary table generation, t-tests, ANOVA, etc., with visualizations like boxplots and swarmplots) and continuous time-series analysis using Statistical Parametric Mapping (SPM). The system is designed to optimize information interpretation, significantly reduce processing times, and streamline the analysis workflow, providing professionals and researchers with efficient access to crucial information. Additionally, KineViz includes robust backup, restore, and undo delete functionalities, ensuring data integrity and availability.

     **Keywords:** kinesiology, biomechanics, data analysis, software, Independent Variables, SPM, automation, data visualization, backup.

       **Texto recomendado para reemplazar el contenido actual de estas subsecciones (Modelo de Datos y Modelo Relacional):**
       "El modelo de datos de KineViz ha evolucionado para soportar una estructura de estudios flexible basada en Variables Independientes (VIs). La persistencia de datos se maneja principalmente a través de una base de datos SQLite, gestionada por `kineviz.database.repositories.StudyRepository`.

       **Componentes Clave del Modelo de Datos Actual:**

       1.  **Estudio (`estudios` tabla en DB):**
           *   Representa una investigación o proyecto.
           *   **Atributos Principales:**
               *   `id_estudio` (INTEGER, PK): Identificador único del estudio.
               *   `nombre_estudio` (TEXT, UNIQUE): Nombre descriptivo del estudio.
               *   `num_sujetos` (INTEGER): Cantidad máxima de participantes previstos. (Anteriormente `num_sujetos`, ahora conceptualmente "participantes").
               *   `cantidad_intentos_prueba` (INTEGER): Número máximo de intentos por condición.
               *   `independent_variables` (TEXT): Almacena una estructura JSON que define las Variables Independientes (VIs) del estudio y sus respectivos sub-valores (descriptores). Cada VI tiene un nombre, una lista de sub-valores, y atributos como `allows_combination` y `is_mandatory`.
               *   `aliases` (TEXT): Almacena una estructura JSON que mapea sub-valores de las VIs a alias definidos por el usuario para ese estudio, mejorando la legibilidad.
               *   `is_pinned` (INTEGER): Indica si el estudio está fijado en la lista principal (0 = no fijado, 1 = fijado).
               *   `comentario` (TEXT): Un campo para notas o descripciones adicionales sobre el estudio. (Reemplaza la antigua columna `descripcion`).

       2.  **Participante (Conceptual, no una tabla separada):**
           *   Representa a un individuo cuyos datos se recolectan. El término "Participante" reemplaza a "Sujeto".
           *   Los datos de los participantes se asocian al estudio a través de los nombres de archivo y la estructura de carpetas. El `ID_Participante` es parte del nombre de archivo.

       3.  **Archivo (Conceptual, gestionado por `FileService` y estructura de carpetas):**
           *   Representa un archivo de datos crudo o procesado.
           *   **Nombre de Archivo:** Sigue un formato estricto: `ID_Participante [SubValor_VI1] [SubValor_VI2] ... [SubValor_VIn] NN.ext`. Por ejemplo: `P01 CMJ PRE 01.txt`. Este formato es crucial para la validación y agrupación automática.
           *   Los archivos se organizan en una estructura de carpetas: `estudios/[NOMBRE_ESTUDIO]/[ID_PARTICIPANTE]/OG/` para originales y `estudios/[NOMBRE_ESTUDIO]/[ID_PARTICIPANTE]/[TIPO_DATO]/` para procesados.

       4.  **Tipo de Dato (Conceptual, no una tabla separada en DB):**
           *   Se refiere a la naturaleza de los datos medidos (ej: Cinemática, Cinética, EMG).
           *   Se determina automáticamente durante el procesamiento de archivos (basado en el contenido o metadatos del archivo, ver `file_handlers.leer_seccion` y Fase 1 del `ROADMAP.md`).
           *   Se utiliza para organizar archivos procesados en subcarpetas y para filtrar análisis. No existe una tabla `Tipos_de_Dato` como entidad separada en la base de datos actual.

       5.  **Cálculos y Resultados de Análisis (Gestionados por `AnalysisService` y estructura de carpetas):**
           *   Los resultados de análisis discretos (tablas resumen, gráficos individuales) y continuos (configuraciones, resultados SPM, gráficos) se almacenan en subcarpetas específicas dentro de la carpeta de cada estudio (ej. `Analisis Discreto/Tablas/`, `Analisis Discreto/Graficos/`, `Analisis Continuo/`).
           *   Las configuraciones de análisis y metadatos clave (como p-valores) se guardan en archivos JSON junto a los gráficos.

       **Modelo Relacional (Conceptual):**
       El modelo relacional se simplifica significativamente en la base de datos, ya que gran parte de la complejidad (VIs, alias, estructura de archivos) se maneja mediante JSON en la tabla `estudios` y la estructura del sistema de archivos.
       *   La tabla principal es `estudios`.
       *   No existen tablas separadas para `Sujeto`, `Archivo`, `Tipo_de_Dato` o `Calculo` como se describía en el modelo anterior. Estas entidades son ahora conceptuales o manejadas por la lógica de la aplicación y la organización de archivos.
       *   Las relaciones entre un estudio y sus VIs/alias están contenidas dentro de los campos JSON de la tabla `estudios`.
       *   La relación entre un estudio y sus archivos/datos de participantes se establece mediante la estructura de carpetas y la validación de nombres de archivo contra las VIs del estudio.

**10. Glosario (Página iv del PDF, al inicio del documento)**

    - **Textos recomendados para actualizar/añadir términos en el Glosario:**
        -   **Variable Independiente (VI):** "Para KineViz, se trata de una categoría o factor que se quiere estudiar o controlar en una investigación (ej: 'Tipo de Salto', 'Condición del Participante', 'Grupo de Edad'). Cada VI se define con uno o más sub-valores (descriptores) que representan los diferentes niveles o tratamientos de esa variable. El orden y la configuración de las VIs son fundamentales para la estructura del estudio y el nombrado de archivos."
        -   **Sub-valor (Descriptor):** "Un nivel, categoría o valor específico dentro de una Variable Independiente (VI). Por ejemplo, si la VI es 'Tipo de Salto', los sub-valores podrían ser 'CMJ', 'SJ', 'DropJump'. Los sub-valores se utilizan en los nombres de archivo para identificar las condiciones de cada medición y para agrupar datos en los análisis."
        -   **Alias:** "Nombre alternativo, más descriptivo o amigable, que el usuario puede asignar a un sub-valor (descriptor) específico dentro de un estudio. Los alias se utilizan en la interfaz de KineViz (ej. leyendas de gráficos, tablas de resultados) para mejorar la legibilidad e interpretación, sin cambiar el sub-valor original usado en los nombres de archivo."
        -   **Tipo de Dato:** "Clasificación de los datos biomecánicos según su naturaleza y origen (ej: Cinemática, Cinética, Electromiografía - EMG). KineViz detecta automáticamente el tipo de dato a partir del contenido de los archivos procesados y lo utiliza para organizar los datos y filtrar los análisis." (Reemplaza o clarifica el uso anterior de "Frecuencia" si se refería a esto).
        -   **SPM (Statistical Parametric Mapping / Mapeo Estadístico Paramétrico):** "Técnica estadística utilizada en KineViz para el análisis de datos continuos o series temporales (ej. curvas de ángulos o momentos a lo largo de un ciclo de movimiento). Permite identificar diferencias significativas entre grupos o condiciones a lo largo de toda la serie temporal, en lugar de solo en puntos discretos."
        -   **Participante:** "Individuo cuyos datos biomecánicos son recolectados y analizados dentro de un estudio en KineViz. Este término reemplaza a 'Sujeto' para una mayor consistencia y adecuación."
        -   **Nulo (Valor de Descriptor):** "Palabra clave especial ('Nulo') que se utiliza en los nombres de archivo para indicar que un descriptor específico de una Variable Independiente (VI) no aplica o no está presente para una medición particular. Su uso está sujeto a las reglas de configuración de la VI (si permite 'Nulo' o no)."
        -   **Copia de Seguridad (Backup):** "Proceso de guardar una copia del estado actual del sistema KineViz (base de datos, archivos de configuración, datos de estudios y análisis) para proteger contra la pérdida de datos. Pueden ser automáticas, manuales o de tipo 'Respaldo' (pre-restauración)."
        -   **Restauración (Restore):** "Proceso de devolver el sistema KineViz a un estado anterior utilizando una copia de seguridad guardada."
        -   **Deshacer Eliminación (Undo Delete):** "Funcionalidad que permite revertir la última operación de eliminación soportada (ej. de un estudio, archivos, o resultados de análisis), restaurando los elementos desde una caché temporal."
